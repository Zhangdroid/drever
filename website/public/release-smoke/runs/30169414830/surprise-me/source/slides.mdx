</Note>

<div className="gate-slide contract-slide">
  <div className="claim-column">
    <p className="eyebrow">The checkpoint contract</p>
    <h2>Make the pause answer four questions.</h2>
    <p className="lead">A confirmation dialog is friction. A checkpoint transfers responsibility.</p>
    <div className="contract-ring" aria-hidden="true"></div>
  </div>

  <div>
    <div className="question-set" role="list" aria-label="Four questions for a meaningful human checkpoint.">
      <div className="question" role="listitem"><b>01 / Intent</b><span>What will happen?</span></div>
      <div className="question" role="listitem"><b>02 / Scope</b><span>Who or what is affected?</span></div>
      <div className="question" role="listitem"><b>03 / Evidence</b><span>What should I inspect?</span></div>
      <div className="question" role="listitem"><b>04 / Recovery</b><span>How can we undo it?</span></div>
    </div>
  </div>
</div>

<Note>
A useful checkpoint is legible before the click. It states the action, exposes the affected scope, presents the evidence worth reviewing, and makes recovery concrete. If the interface cannot answer these questions, “Are you sure?” only performs safety.
</Note>

    </section>
    <section className="lane deliberate">
      <h3>Deliberate lane</h3>
      <div className="lane-rule">External action · durable state · meaningful blast radius</div>
      <div className="lane-mode">Explicit approval</div>
    </section>
  </div>
</div>

<Note>
This is the practical synthesis. The goal is not to slow the entire system to the speed of its riskiest step. Let reversible work move quickly. Spend scarce human attention only where the workflow crosses into consequential action—and make that attention high quality.
</Note>
