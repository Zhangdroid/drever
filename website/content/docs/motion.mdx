<h2 id="semantic-motion">Motion starts with meaning</h2>

Drever does not ask authors to choose easing curves or entrance presets. Authors describe the
narrative relationship; the active theme decides how that relationship moves.

| Intent       | Use it when                                                           |
| ------------ | --------------------------------------------------------------------- |
| `focus`      | Earlier points remain visible while the newest point becomes primary. |
| `replace`    | One stable frame exchanges one state for another.                     |
| `compare`    | Revealed evidence must remain readable as peers.                      |
| `stagger`    | Up to four parts form one explanatory beat.                           |
| `continuity` | The same object persists across adjacent slides.                      |

<h2 id="focus-replace-compare">Focus, replace, and compare</h2>

These intents use direct `Step` children:

```mdx
<MotionGroup intent="focus" flow="block">
  <Step>Frame the question.</Step>
  <Step>Reveal the evidence.</Step>
  <Step>Make the decision.</Step>
</MotionGroup>
```

Use `flow="block"` for vertical reading order and `flow="inline"` for a horizontal pipeline or
comparison. Flow provides meaning to the theme; it does not create layout.

<h2 id="stagger">Stagger without adding navigation stops</h2>

Put `stagger` inside one Step. One advance reveals the complete group:

```mdx
<Step>
  <MotionGroup intent="stagger" flow="inline">
    <div>Parse</div>
    <div>Compile</div>
    <div>Verify</div>
    <div>Ship</div>
  </MotionGroup>
</Step>
```

If the audience needs to discuss an item separately, author separate Steps instead.

<h2 id="continuity">Continuity across slides</h2>

Give the same explicit name to the same object on adjacent slides:

```mdx
<MotionGroup intent="continuity" name="decision-card">
  <DecisionCard />
</MotionGroup>
```

Carry identity, not resemblance. A matching color or shape does not make two objects the same.
Keep the captured shell's size, aspect ratio, typography, and media crop deliberate. Changing prose
usually belongs outside the shared bitmap.

<h2 id="principles">The non-negotiable principles</h2>

1. Motion explains focus, order, replacement, comparison, or continuity. Otherwise omit it.
2. Give each moment one primary motion and at most one quieter supporting cue. Steps, native
   transitions, kinetic type, video, 3D, and third-party animation share that budget.
3. Move the smallest meaningful object. Background, title, controls, and page chrome stay put.
4. Keep recurring geometry, wrapping, paint, and shadow lists stable.
5. Never clip a surface whose shadow or glow must remain visible.
6. Mark the active Step without dimming an entire completed Step below readable contrast.
7. Review intermediate frames, backward navigation, reduced motion, speaker, document, and export.

The eight official design studies deliberately use different motion voices. The same intent can feel
calm in Default, editorial in Editorial, precise in Studio, handwritten in Fieldnote, directional
in Atlas, accountable in Ledger, cinematic in Cinema, or assembled in Construct.

<h2 id="object-lifecycle">Plan a role, not an entrance</h2>

A key object can hint just below the canvas, enter when it becomes evidence, dock at a quiet edge
while the explanation takes focus, and retire when it stops helping. Use only the beats the story
needs. A browser frame that moves from demonstration to low-contrast context explains a changing
narrative role; four unrelated entrance effects do not.

Keep one motion owner per element. Use native continuity between slides or local live-DOM motion
inside one slide, never both at once.

<h2 id="external-tools">Bring focused capabilities</h2>

[React Bits](https://reactbits.dev/) can inspire a kinetic-type or background technique, and
[Spline](https://docs.spline.design/exporting-your-scene/web/exporting-as-code) can supply a spatial
model when depth improves the explanation. They are examples, not Drever dependencies or visual
presets. Prefer native CSS and small local React for simple motion. Before copying code, assets, or
runtimes, inspect current official documentation, source, license, bundle behavior, and export
constraints, then adapt the technique to the deck's subject-led design.

Every live integration needs accessible final meaning, keyboard behavior, deterministic loading
and export readiness, reduced-motion output, and a stable poster or authored fallback when document
or export surfaces should not run it. Keep continuous backgrounds and 3D subordinate to the claim.
